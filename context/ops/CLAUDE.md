# Ops Agent Context — Magenta

## Domain Overview

Ops owns the deployment, infrastructure, observability, and governance of the entire agent fabric. This includes IaC (Bicep/Terraform), CI/CD pipelines, RBAC enforcement, monitoring dashboards, and incident response procedures.

## Technology Stack

- **IaC:** Bicep (primary) · Terraform (alternative)
- **CI/CD:** GitHub Actions · Azure DevOps
- **Observability:** Azure Monitor · Application Insights · Log Analytics
- **Secrets:** Azure Key Vault
- **Container:** AKS (if needed for Elasticsearch or custom agents)
- **Policy:** Azure Policy · Sentinel custom detections for fabric health

## Infrastructure Architecture

All resources follow a naming convention: `{env}-{region}-{resource-type}-{purpose}` (e.g., `prod-eastus-eventhub-alerts`).

## Conventions

- **IaC:** All infrastructure defined as code; no manual portal changes
- **Branching:** `main` = production; `staging` = pre-prod; feature branches from `main`
- **Deployment:** CI/CD must pass all QA gates before reaching `main`
- **Tags:** Every resource tagged with `env`, `bu`, `cost-center`, `owner`
- **Retention:** Log Analytics 90-day default; longer retention requires explicit IaC override
- **Alerting:** All alerts route to a central Action Group; P1 alerts page the Agent Ops Engineer

## Guardrails

- NEVER use shared service accounts — every agent gets its own managed identity
- NEVER assign `Contributor` or `Owner` at subscription scope — scope to resource group + specific actions
- NEVER store secrets in GitHub Secrets that haven't been cycled in the last 90 days
- NEVER deploy to production on Friday without a rollback plan approved by SOC Manager
- NEVER disable Azure Policy assignments without architecture board approval
- ALWAYS enable Defender for Cloud on subscriptions hosting the fabric
- ALWAYS enforce branch protection on `main` (required reviews, status checks, no direct pushes)
- ALWAYS configure dead-letter alerts for Event Hubs — silent failures are unacceptable
- ALWAYS run `terraform plan` / `what-if` in CI and require human approval for production changes

## Cross-Domain Interfaces

| Domain | Interface | Protocol |
|---|---|---|
| Backend | Deploy Function Apps, Logic Apps, Event Hubs | CI/CD + IaC |
| Data | Deploy Data Lake, Elasticsearch, Sentinel tables | CI/CD + IaC |
| Frontend | Deploy portal, dashboards | CI/CD + IaC |
| QA | Gate deployments on test results | CI/CD pipeline |
| Security | RBAC review, policy compliance | Azure Policy + weekly audit |

## Feedback Loops

- Weekly RBAC review report generated by Azure Policy and emailed to architecture board
- Monthly architecture change review (TOGAF Phase H) for any new agent, data source, or action type
- Incident response drill quarterly with SOC team — test agent malfunction, Event Hubs outage, Data Lake unavailability
- Cost optimization review monthly — right-sizing Event Hubs throughput units, Elasticsearch tier adjustments, Data Lake lifecycle policy effectiveness
